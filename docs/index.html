01. Giới thiệu đề tài

Điện toán đám mây là một mô hình cung cấp tài nguyên công nghệ thông tin thông qua Internet. Thay vì phải đầu tư và quản lý toàn bộ máy chủ vật lý, người dùng có thể sử dụng tài nguyên tính toán, lưu trữ và môi trường phát triển được cung cấp bởi nhà cung cấp dịch vụ.

Trong bài thực hành này, sinh viên sử dụng GitHub Codespaces để tạo một môi trường lập trình trực tuyến, khởi tạo dự án Node.js và xây dựng API Hello Cloud. API có khả năng cung cấp thông tin về môi trường thực thi như tên máy chủ, số lượng CPU, dung lượng bộ nhớ, hệ điều hành và thời gian hoạt động.

Sau khi xây dựng thành công, ứng dụng được truy cập thông qua trình duyệt và thiết bị di động. Sinh viên đồng thời sử dụng GitHub Pages để xuất bản trang báo cáo kết quả thực hành.

Ý nghĩa bài thực hành: Giúp sinh viên trải nghiệm trực tiếp quy trình cấp phát môi trường điện toán đám mây, phát triển ứng dụng, truy cập dịch vụ qua Internet và theo dõi mức sử dụng tài nguyên.

02. Mục tiêu thực hiện

01

Môi trường đám mây

Tạo và sử dụng môi trường lập trình trực tuyến thay cho việc cài đặt toàn bộ môi trường trên máy tính cá nhân.

02

Xây dựng API

Sử dụng Node.js và Express để xây dựng API có khả năng trả về dữ liệu JSON.

03

Truy cập Internet

Kiểm tra khả năng truy cập ứng dụng từ nhiều thiết bị thông qua URL công khai.

04

Đặc tính NIST

Nhận diện năm đặc tính cơ bản của điện toán đám mây thông qua trải nghiệm thực tế.

Kết quả mong đợi

  • Tạo thành công một GitHub Codespace.
  • Khởi tạo dự án Node.js và cài đặt Express.
  • Xây dựng API GET / trả về dữ liệu JSON.
  • Truy cập API bằng điện thoại thông qua Internet.
  • Triển khai trang báo cáo bằng GitHub Pages.
  • Phân tích và liên hệ năm đặc tính NIST.

04. Quy trình thực hiện

1

Tạo repository trên GitHub

Sử dụng repository template của giảng viên để tạo repository mới với tên notes-api-MSSV. Repository được thiết lập ở chế độ Public để thuận tiện cho việc quản lý và kiểm tra mã nguồn.

2

Khởi chạy GitHub Codespaces

Tạo một Codespace từ nhánh main của repository. Hệ thống cung cấp môi trường phát triển trực tuyến với terminal và trình soạn thảo mã nguồn tích hợp.

3

Khởi tạo dự án Node.js

Sử dụng npm init -y để khởi tạo dự án, cài đặt Express và tạo các thư mục src, docs nhằm tổ chức mã nguồn và tài liệu.

4

Xây dựng API Hello Cloud

Tạo hai tệp app.js và server.js. Tệp app.js xử lý logic ứng dụng, còn server.js chịu trách nhiệm khởi động máy chủ tại cổng 3000.

5

Kiểm tra khả năng truy cập

Mở cổng 3000 và chuyển Port Visibility sang Public để kiểm tra API trên thiết bị di động. Sau khi hoàn tất, chuyển lại Private.

6

Đo lường và so sánh tài nguyên

Thu thập thông tin CPU, RAM, hệ điều hành từ API trên máy cá nhân và Codespace. Đồng thời kiểm tra mức sử dụng tại GitHub Billing Usage.

7

Triển khai GitHub Pages

Xây dựng trang báo cáo HTML trong thư mục docs, commit mã nguồn và cấu hình GitHub Pages để xuất bản trang web.

05. Xây dựng API Hello Cloud

5.1. Giới thiệu API

API Hello Cloud được xây dựng bằng Node.js và Express. API sử dụng phương thức HTTP GET tại đường dẫn gốc "/" để cung cấp thông tin của môi trường đang thực thi ứng dụng.

5.2. Các thông tin API cung cấp

Trường dữ liệu Ý nghĩa
message Thông điệp chào mừng từ ứng dụng.
host Tên máy chủ đang thực thi ứng dụng.
platform Thông tin hệ điều hành.
cpus Số lượng CPU logic được Node.js nhận diện.
memoryGB Tổng bộ nhớ RAM được hệ điều hành báo cáo, đổi sang GB.
uptimeSec Thời gian hoạt động của hệ điều hành tính bằng giây.
time Thời điểm API tạo phản hồi theo định dạng ISO.

5.3. Phương thức truy cập

HTTP Method: GET
Endpoint: /
Port: 3000
Response: application/json

5.4. Kết quả kiểm thử

Sau khi chạy lệnh npm start, máy chủ Express tiếp nhận yêu cầu trên cổng 3000. Khi người dùng truy cập endpoint gốc, ứng dụng trả về một đối tượng JSON chứa thông tin môi trường thực thi. 

{
  "message": "Xin chào từ đám mây!",
  "host": "TEN_MAY_CHU_THUC_TE",
  "platform": "Linux ...",
  "cpus": "...",
  "memoryGB": "...",
  "uptimeSec": "...",
  "time": "..."
}
Kết quả: API được kiểm tra bằng trình duyệt thông qua endpoint GET /. Các trường dữ liệu được trả về dưới dạng JSON.

Máy tính cá nhân yêu cầu người dùng tự cài đặt và quản lý môi trường phát triển. GitHub Codespaces cho phép tạo môi trường lập trình trên nền tảng đám mây, truy cập thông qua trình duyệt và sử dụng tài nguyên được cấp phát từ nhà cung cấp.

6.1. Phân tích môi trường máy cá nhân

Khi sử dụng máy tính cá nhân, người dùng có quyền chủ động quản lý hệ điều hành, cài đặt Node.js, npm và các thư viện cần thiết. Tài nguyên sử dụng phụ thuộc vào cấu hình phần cứng của máy tính.

6.2. Phân tích môi trường Codespace

Với GitHub Codespaces, môi trường phát triển được cung cấp trực tuyến. Người dùng có thể truy cập trình soạn thảo và terminal thông qua trình duyệt mà không cần tự thiết lập toàn bộ máy chủ vật lý.

6.3. Nhận xét

Hai môi trường đều có thể thực thi ứng dụng Node.js. Tuy nhiên, Codespaces có lợi thế về khả năng truy cập từ nhiều thiết bị, đồng bộ môi trường phát triển và quản lý mã nguồn tập trung. Máy cá nhân có lợi thế về quyền kiểm soát phần cứng và khả năng làm việc ngoại tuyến khi đã chuẩn bị đầy đủ môi trường.

07. Đối chiếu 5 đặc tính điện toán đám mây NIST

Theo mô hình điện toán đám mây của NIST, điện toán đám mây có năm đặc tính thiết yếu. Các đặc tính này có thể được nhận diện thông qua quá trình sử dụng GitHub Codespaces.

ĐẶC TÍNH 01

On-demand Self-service - Tự phục vụ theo yêu cầu

Người dùng có thể tự tạo một Codespace thông qua giao diện GitHub mà không cần yêu cầu quản trị viên cấp phát máy chủ thủ công.

Thao tác thực tế:

Chọn Code → Codespaces → Create codespace on main.

Ý nghĩa:

Tài nguyên điện toán có thể được yêu cầu và cấp phát theo nhu cầu sử dụng của người dùng.

ĐẶC TÍNH 02

Broad Network Access - Truy cập mạng rộng

Các dịch vụ đám mây có thể được truy cập thông qua mạng bằng những thiết bị khác nhau. Trong bài thực hành, API được truy cập từ máy tính và điện thoại thông qua URL HTTPS.

Thao tác thực tế:

Chuyển Port Visibility của cổng 3000 sang Public và mở URL trên điện thoại.

Ý nghĩa:

Người dùng có thể sử dụng dịch vụ từ nhiều thiết bị có kết nối Internet và được cấp quyền truy cập phù hợp.

ĐẶC TÍNH 03

Resource Pooling - Gộp tài nguyên

Nhà cung cấp sử dụng hạ tầng tài nguyên điện toán dùng chung để phục vụ nhiều người dùng. Tài nguyên được phân bổ linh hoạt theo nhu cầu của các môi trường.

Thao tác thực tế:

Tạo Codespace và sử dụng CPU, RAM được cung cấp bởi nền tảng GitHub Codespaces.

Ý nghĩa:

Người dùng không cần trực tiếp sở hữu máy chủ vật lý riêng để chạy môi trường phát triển. Việc quan sát hostname không đủ để xác định máy chủ vật lý cụ thể.

ĐẶC TÍNH 04

Rapid Elasticity - Co giãn nhanh

Tài nguyên điện toán có khả năng được cấp phát, thay đổi hoặc giải phóng nhanh theo nhu cầu. Người dùng có thể tạo Codespace với cấu hình phù hợp và thay đổi loại máy khi được hỗ trợ.

Thao tác thực tế:

Tạo, dừng và quản lý Codespace. Việc thay đổi cấu hình máy có thể thực hiện thông qua lựa chọn machine type được GitHub hỗ trợ.

Ý nghĩa:

Khả năng sử dụng tài nguyên linh hoạt giúp hạn chế việc phải duy trì máy chủ riêng liên tục khi không có nhu cầu.

ĐẶC TÍNH 05

Measured Service - Dịch vụ đo lường được

Việc sử dụng tài nguyên được theo dõi và đo lường thông qua những chỉ số phù hợp. Người dùng có thể kiểm tra mức sử dụng Codespaces trong trang Billing Usage.

Thao tác thực tế:

Truy cập GitHub Settings → Billing → Usage để kiểm tra mức sử dụng Core-hours và dung lượng lưu trữ.

Ý nghĩa:

Việc đo lường giúp người dùng theo dõi mức tiêu thụ tài nguyên và quản lý chi phí dịch vụ đám mây.

08. Đánh giá và phân tích kết quả

8.1. Những kết quả đạt được

  • Khởi tạo thành công môi trường lập trình trực tuyến trên GitHub Codespaces.
  • Cài đặt và sử dụng Node.js cùng Express để phát triển ứng dụng phía máy chủ.
  • Tách biệt logic ứng dụng và thành phần khởi động máy chủ.
  • Xây dựng API cung cấp thông tin môi trường thực thi thông qua định dạng JSON.
  • Kiểm tra khả năng truy cập ứng dụng bằng thiết bị di động.
  • Sử dụng GitHub Pages để xuất bản nội dung báo cáo.

8.2. Ưu điểm của môi trường điện toán đám mây

Môi trường lập trình trên đám mây giúp giảm sự phụ thuộc vào cấu hình máy tính cá nhân. Người dùng có thể truy cập môi trường làm việc từ nhiều thiết bị, đồng thời sử dụng repository để lưu trữ và đồng bộ mã nguồn.

Ngoài ra, việc sử dụng dịch vụ trực tuyến giúp quá trình thiết lập môi trường phát triển thuận tiện hơn, đặc biệt trong trường hợp sinh viên cần làm việc trên nhiều máy tính khác nhau.

8.3. Hạn chế và rủi ro

  • Cần có kết nối Internet ổn định để truy cập và sử dụng môi trường đám mây.
  • Có thể phát sinh chi phí khi vượt hạn mức sử dụng miễn phí.
  • Phụ thuộc vào chính sách và khả năng cung cấp dịch vụ của nhà cung cấp.
  • Cấu hình cổng Public không phù hợp có thể khiến dịch vụ bị truy cập ngoài dự kiến.
  • Người dùng cần quản lý quyền truy cập, mã nguồn và thông tin nhạy cảm một cách cẩn thận.

8.4. So sánh với phương pháp truyền thống

Trong phương pháp truyền thống, sinh viên thường phải cài đặt môi trường lập trình trên từng máy tính trong phòng thực hành. Điều này có thể dẫn đến sự khác biệt về phiên bản phần mềm và cấu hình giữa các máy.

Với Codespaces, môi trường phát triển được cung cấp trực tuyến và gắn với repository. Nhờ đó, việc tiếp cận môi trường lập trình trở nên thuận tiện và dễ đồng bộ hơn.

09. Câu hỏi phản biện

Câu 1. Trường host có thay đổi sau khi Stop và Start Codespace không?

Trường host có thể thay đổi hoặc giữ nguyên sau khi Codespace được dừng và khởi động lại. Nếu hostname thay đổi, điều đó cho thấy môi trường có thể được cấp phát lại với một định danh máy chủ khác. Nếu hostname giữ nguyên thì không thể kết luận máy chủ vật lý không thay đổi, vì hostname không nhất thiết xác định máy chủ vật lý.

Câu 2. GitHub Codespaces thuộc IaaS, PaaS hay SaaS?

GitHub Codespaces gần với mô hình PaaS xét theo trải nghiệm sử dụng. GitHub cung cấp hạ tầng và môi trường phát triển được quản lý, trong khi người dùng phát triển mã nguồn, cài đặt các gói phần mềm và quản lý ứng dụng. Người dùng không phải trực tiếp quản lý máy chủ vật lý và hạ tầng bên dưới.

Câu 3. Hai hạn chế truyền thống được khắc phục và một rủi ro mới?

Hai hạn chế được khắc phục là việc phải cài đặt môi trường lập trình riêng trên từng máy tính và khó đồng bộ cấu hình phần mềm giữa các máy trong phòng lab. Codespaces cung cấp môi trường trực tuyến và giúp quản lý mã nguồn tập trung.

Rủi ro mới là phụ thuộc vào kết nối Internet và nhà cung cấp dịch vụ đám mây. Ngoài ra, việc cấu hình quyền truy cập không phù hợp có thể gây lộ dịch vụ hoặc dữ liệu.

10. Kết luận

Qua bài thực hành, sinh viên đã tiếp cận quy trình xây dựng và triển khai một ứng dụng cơ bản trên môi trường điện toán đám mây thông qua GitHub Codespaces.

Việc sử dụng Node.js và Express giúp xây dựng API Hello Cloud có khả năng trả về các thông tin của môi trường thực thi. Đồng thời, việc truy cập API từ thiết bị di động cho thấy khả năng cung cấp dịch vụ thông qua mạng.

Bài thực hành cũng giúp liên hệ năm đặc tính thiết yếu của NIST với các thao tác thực tế, bao gồm tự phục vụ theo yêu cầu, truy cập mạng rộng, gộp tài nguyên, co giãn nhanh và dịch vụ đo lường được.

Thông qua GitHub Pages, kết quả thực hiện được xuất bản thành một trang báo cáo trực tuyến. Đây là nền tảng để tiếp tục phát triển và tái sử dụng mã nguồn trong các bài thực hành tiếp theo.

Tổng kết: Hoàn thành các nội dung xây dựng API, kiểm tra môi trường đám mây, đối chiếu đặc tính NIST và xuất bản báo cáo trực tuyến.
